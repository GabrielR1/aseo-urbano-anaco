## 1. RESUMEN EJECUTIVO DEL DIAGNÓSTICO

El sistema EcoRuta cumple con los requisitos funcionales mínimos (CRUD, rastreo GPS, incidencias). Sin embargo, **presenta deudas técnicas críticas** que impedirían su despliegue en un entorno real con múltiples usuarios concurrentes:

- **Riesgo mayor:** Uso de **SQLite** en entornos productivos (bloqueos de escritura, sin extensión geoespacial).
- **Riesgo mayor:** Claves secretas y credenciales **hardcodeadas** en el código fuente.
- **Riesgo alto:** La app móvil **pierde datos de GPS** si no hay cobertura de red.
- **Riesgo alto:** El mapa web usa **polling continuo**, generando sobrecarga innecesaria.

El presente informe desglosa las acciones correctivas, clasificadas por nivel de urgencia.

## 2. PLAN DE ACCIÓN POR PRIORIDADES

### 🔴 CRÍTICO (Ejecutar antes del despliegue a producción)

| ID | Área | Problema | Solución Propuesta | Comando / Acción Concreta |
| :--- | :--- | :--- | :--- | :--- |
| **C-01** | **Base de Datos** | SQLite no soporta concurrencia real ni cálculos geoespaciales. | Migrar a **PostgreSQL** (sin PostGIS inicialmente, se añade después). | `pip install psycopg2-binary`<br>Cambiar `ENGINE` a `django.db.backends.postgresql` en `settings.py`.<br>Ejecutar `python manage.py migrate`. |
| **C-02** | **Seguridad** | `SECRET_KEY`, credenciales de DB y URLs expuestas en `settings.py`. | Implementar variables de entorno con `django-environ`. | `pip install django-environ`<br>Crear `.env` (excluido del `.gitignore`).<br>Modificar `settings.py` para leer desde `env('SECRET_KEY')`. |
| **C-03** | **Seguridad** | CORS abierto (`*`) o mal configurado. | Restringir CORS solo a los dominios de la app móvil y el panel web. | `pip install django-cors-headers`<br>Configurar `CORS_ALLOWED_ORIGINS = ['https://tu-dominio.com', 'app-ecoruta://']`. |
| **C-04** | **Backend** | Las fotos de incidencias se guardan como ruta de texto sin manejo de archivos. | Usar `FileField` con `upload_to='incidencias/'` y servir con `MEDIA_URL`. | Modificar el modelo `Incidencia`.<br>Configurar `MEDIA_ROOT` y `MEDIA_URL`.<br>Usar `request.FILES` en la vista de la API. |

### 🟠 ALTA PRIORIDAD (Siguiente sprint)

| ID | Área | Problema | Solución Propuesta | Comando / Acción Concreta |
| :--- | :--- | :--- | :--- | :--- |
| **A-01** | **Seguridad (Auth)** | Token simple de DRF (sin renovación) expone al usuario a sesiones indefinidas. | Implementar **JWT con Refresh Token** (Simple JWT). | `pip install djangorestframework-simplejwt`<br>Configurar urls para `/token/` y `/token/refresh/`.<br>En Flutter, usar **interceptor con Dio** para refrescar automáticamente. |
| **A-02** | **Backend (Modelos)** | La `Jornada` solo tiene `fecha` (no hora real de inicio/fin). | Agregar campos `inicio_real` y `fin_real` (DateTimeField, null=True). | Crear migración y actualizar la lógica al iniciar/finalizar jornada. |
| **A-03** | **Backend (Modelos)** | `PuntoGeolocalizacion` carece de precisión y velocidad. | Añadir `precision_metros` (FloatField) y `velocidad_kmh` (FloatField, opcional). | Crear migración. Actualizar el endpoint de Flutter para enviar estos datos (Geolocator los provee). |
| **A-04** | **Rendimiento** | Consultas sin índices y sin `select_related` en listados. | - Agregar `db_index=True` a `timestamp` y `fecha`.<br>- Forzar `select_related('vehiculo', 'ruta', 'chofer')` en las vistas de listado de Jornadas. | Modificar `views.py` y `models.py`.<br>Verificar con `django-debug-toolbar`. |
| **A-05** | **Rendimiento (API)** | Endpoints de GPS e incidencias devuelven todos los registros sin paginación. | Aplicar `PageNumberPagination` (ej. 50 registros por página). | Agregar `pagination_class` en las `ViewSet` o `GenericAPIView`. |
| **A-06** | **Flutter (Offline)** | Si el chofer pierde internet, los puntos GPS se pierden para siempre. | Implementar almacenamiento local **Hive** o **SQLite** para hacer cola de sincronización. | `flutter pub add hive hive_flutter`<br>Guardar puntos localmente al fallar la petición HTTP.<br>Crear un `BackgroundSync` al recuperar la red. |
| **A-07** | **Flutter (Imagenes)** | Las fotos se suben en tamaño original (alto consumo de datos). | Comprimir la imagen antes de subir (reducir calidad a 60-70% y redimensionar a 1024px). | Usar `flutter_native_image` o `image_picker` con opción `imageQuality: 70`. |

### 🟡 MEDIA PRIORIDAD (Fase 2 del Roadmap)

| ID | Área | Problema | Solución Propuesta | Comando / Acción Concreta |
| :--- | :--- | :--- | :--- | :--- |
| **M-01** | **Tiempo Real** | Mapa web actualiza por polling (HTTP cada N segundos). Ineficiente. | Implementar **Django Channels + WebSockets + Redis** para transmitir coordenadas en tiempo real. | `pip install channels channels-redis`<br>Configurar `ASGI_APPLICATION`.<br>Flutter se conecta al WebSocket para enviar puntos. El navegador los recibe y pinta en Leaflet sin recargar. |
| **M-02** | **Notificaciones** | El chofer no recibe alerta cuando se le asigna una nueva jornada. | Integrar **Firebase Cloud Messaging (FCM)** para Push Notifications. | Configurar FCM en Django (enviar notificación al crear/actualizar Jornada).<br>En Flutter, usar `firebase_messaging` para recibir y mostrar la notificación. |
| **M-03** | **Reportes** | No hay exportación de informes (solo visualización en pantalla). | Generar reportes en **PDF (ReportLab)** y **Excel (openpyxl)** desde el panel web. | Crear botones "Exportar" en las vistas de Recursos e Itinerario.<br>Generar archivo y descargar con `FileResponse`. |
| **M-04** | **Documentación** | La API no tiene documentación interactiva para los desarrolladores. | Implementar **Swagger/OpenAPI** con `drf-spectacular`. | `pip install drf-spectacular`<br>Configurar `SPECTACULAR_SETTINGS`.<br>Agregar url `/api/schema/` y `/api/docs/`. |

### 🟢 ESTRATÉGICO / LARGO PLAZO (Fase 3)

| ID | Área | Problema | Solución Propuesta | Observaciones |
| :--- | :--- | :--- | :--- | :--- |
| **E-01** | **Geoespacial** | No se pueden calcular distancias reales ni geocercas. | Instalar extensión **PostGIS** en PostgreSQL e integrar `django.contrib.gis`. | Permite consultas tipo "camiones dentro de un polígono" o "distancia recorrida real". |
| **E-02** | **Inteligencia** | La ruta es fija (distancia manual). No se optimiza combustible. | Integrar **OR-Tools** (Google) u **OSRM** para calcular la ruta óptima en base a contenedores y tráfico. | Requiere modelar puntos de recolección como nodos. |
| **E-03** | **DevOps** | Sin pruebas automatizadas ni integración continua. | Implementar **pytest** para tests unitarios y de integración.<br>Configurar **GitHub Actions** para correr tests al hacer push. | Escribir tests para endpoints críticos (login, GPS, incidencias). |
| **E-04** | **Auditoría** | No se registra quién modifica cada registro. | Agregar campo `modificado_por` (ForeignKey a User) con señal `pre_save` en cada modelo. | Útil para trazabilidad y requisitos de tesis/calidad. |
